# 광고 해석 설문

모바일 광고 배너를 사람들이 어떻게 받아들이는지 조사하는 대학원 프로젝트입니다. 20~30대와 50~60대의 응답(약 60명)을 자동으로 모으고, 관리자만 결과를 조회·비교·다운로드할 수 있는 웹사이트입니다.

> **현재 상태 (2026-11-11)**
> 설문 응답 저장, 관리자 화면, 보안 규칙을 구현해 Firebase 프로젝트 `adresearch-c4ed5`에 배포했습니다.
> 실제 사이트에서 두 링크의 테스트 응답 저장과 접근 차단을 확인했습니다. 소수 인원으로 예비 조사를 해 본 뒤 테스트 응답을 지우고 본 조사를 시작하세요.

## 구성

| 역할 | 사용 기능 |
| --- | --- |
| 설문·관리자 화면 배포 | Firebase Hosting (일반 Hosting) |
| 응답 저장 | Cloud Firestore (Standard edition) |
| 참여자 구분·관리자 로그인 | Firebase Authentication (익명 / 이메일·비밀번호) |
| 접근 제한 | Firestore Security Rules (`firestore.rules`) |

무료 Spark 플랜 범위에서 동작하도록 만들었습니다. App Hosting, Cloud Functions, Cloud Storage는 쓰지 않습니다. 배너 이미지는 `public/img/`에 두어 사이트와 함께 배포합니다. 별도 빌드 과정이나 분석 서버가 없습니다. 사용량 한도는 [Firebase 요금표](https://firebase.google.com/pricing)에서 확인하세요.

## 참여 링크

| 대상 | 링크 |
| --- | --- |
| 20~30대 모집 | https://adresearch-c4ed5.web.app/?group=young |
| 50~60대 모집 | https://adresearch-c4ed5.web.app/?group=older |
| 관리자 | https://adresearch-c4ed5.web.app/admin |

40대와 70대 이상은 원본 설계대로 첫 질문에서 선별 탈락으로 종료됩니다. 40대를 받으려면 조사 조건 변경으로 처리해야 합니다(아래 ‘조사 설계 확인 기록’).

- 두 링크는 같은 코드와 같은 설문입니다. 문항·보기·참여 제외 조건은 링크와 관계없이 같습니다(확정 사항).
- 링크 그룹(`linkGroup`)과 실제 응답 연령대(`ageGroup`, Q1 답)는 따로 저장합니다. 링크 값은 누구나 바꿀 수 있으므로 실제 나이나 권한으로 쓰지 않습니다.
- `group`이 없거나 `young`/`older`가 아니면 `unknown`으로 기록하고 그대로 진행합니다. 원래 값은 `linkGroupRaw`에 남습니다(확정 사항).
- 링크 그룹과 Q1 연령대가 다르면 `groupMismatch: true`로 기록하고 진행합니다. 선별은 Q1 답 기준입니다(확정 사항). 관리자 화면에서 따로 볼 수 있습니다.

### 주소 뒤 옵션 (원본 기능 유지)

`#` 뒤에 붙이며 `-`로 여러 개를 이을 수 있습니다. 예: `/?group=young#test-t5`

| 옵션 | 동작 |
| --- | --- |
| `test` | 테스트 응답으로 표시. 관리자 기본 집계에서 빠짐. 끝난 뒤 ‘새 테스트 시작’ 가능 |
| `t5`, `t10` | 노출 시간 5초 / 10초 (기본 10초) |
| `o1`~`o3` | 배너 제시 순서의 시작 번호 고정 (기본: 무작위 시작 후 순환) |

`test`와 노출 시간 옵션도 주소를 아는 사람이면 붙일 수 있습니다. 참여자에게는 옵션 없는 링크만 보내세요.

## 설문 흐름 (원본과 동일)

1. 안내와 참여 동의
2. 기본 질문과 선별: 40대·70대 이상, 스마트폰 거의 안 씀, **50~60대 중 광고를 눌러 본 적 없음(Q3_3까지 답한 뒤)·기억 안 남(Q3)**은 종료. 50~60대만의 클릭 경험 조건은 의도한 조건으로 확인되어 유지합니다.
3. 배너 3개 각각: 사진을 설정 시간(기본 10초) 보여 주고 숨김 → 숨긴 상태로 질문(A) → 다시 보여 주며 질문(B, 확신도 포함)
4. 마무리 질문 → 제출 → 저장 확인 후 완료 번호

질문 문구, 보기, 제외 조건, 배너 제시 순서 방식, 노출 시간은 바꾸지 않았습니다. `tests/static`이 원본 HTML의 문항 정의와 글자 단위로 같은지 확인합니다. 가상 서비스 화면 체험은 요구사항이 확정되지 않아 넣지 않았습니다.

| 항목 | 원본 | 지금 |

## 저장과 복구

- **언제 저장하나**: 참여 동의 후 첫 화면으로 넘어갈 때 문서를 만들고, 이후 답을 고를 때마다 1.2초 모아서 중간 저장합니다. 화면을 떠날 때(`visibilitychange`, `pagehide`) 예약된 저장을 바로 보냅니다. 동의 전에는 아무것도 저장하지 않습니다.
- **순서 보장**: 저장마다 `rev`가 1씩 늘고, 규칙이 `rev`가 줄거나 같은 저장을 거부합니다. 종료(완료·선별 탈락·그만하기)하면 예약된 중간 저장을 버리고, 규칙도 종료된 응답의 수정을 거부하므로 늦게 도착한 중간 저장이 최종 응답을 덮어쓰지 못합니다.
- **최종 제출**: 종료 상태를 저장한 뒤 서버에서 다시 읽어(캐시 사용 안 함) 상태가 맞을 때만 완료 화면을 보여 줍니다. 실패하면 ‘아직 저장되지 않았습니다 / 다시 시도’를 보여 주고, 최후 수단으로 답 내용 복사를 제공합니다.
- **중복 제출**: 제출 중에는 다시 제출하지 않습니다. 이미 완료된 응답에 다시 저장하면 규칙이 거부하고, 서버에 완료로 남아 있으면 성공으로 처리합니다.
- **새로고침·창 닫기**: 진행 상태를 브라우저 `localStorage`에 함께 보관합니다. 같은 브라우저에서 같은 링크를 다시 열면 그 화면부터 이어집니다. 노출 화면이었다면 안내 화면부터 다시 보여 주고 반복 노출로 기록합니다. 숨긴 상태의 질문(A)은 사진을 다시 보여 주지 않고 이어서 답합니다. 종료했지만 저장 확인이 안 된 응답은 다시 열면 자동으로 다시 저장합니다.
- **한계**: 시크릿 창, 브라우저 저장공간 삭제, 다른 기기에서는 이어서 할 수 없습니다(새 응답으로 시작).

### 저장 필드 (`responses/{응답ID}`)

| 필드 | 내용 |
| --- | --- |
| `id`, `uid` | 응답 ID(무작위 UUID), 응답 소유자(익명 인증 uid) |
| `surveyVersion`, `rev` | 설문 버전(`public/js/questions.js`의 `SURVEY_VERSION`), 저장 순번 |
| `status`, `endReason` | `in_progress` / `complete` / `screened_out` / `quit`, 선별 사유(`age`, `phone`, `no-experience` + 문항) |
| `test`, `consent` | 테스트 여부, 동의 여부 |
| `linkGroup`, `linkGroupRaw`, `ageGroup`, `groupMismatch` | 모집 링크, URL 원래 값, 실제 응답 연령대(`20-30`/`50-60`/빈 값), 불일치 여부 |
| `order`, `orderSrc`, `optOrder` | 배너 제시 순서, 순서 결정 방식, 문항별 보기 제시 순서 |
| `expSec` | **설정된** 노출 시간(초) |
| `exposures[]` | 노출마다 `banner`, `attempt`, `plannedMs`(설정), `actualMs`(**실제 측정**), `imgWaitMs`, `outcome`(`completed`/`hidden`/`reload`/`img_error`), `at`, `shownAt` |
| `restarts` | 배너별 재노출 횟수 |
| `ans`, `ms` | 문항별 답(확신도 `sN_B4_k`, 직접 쓰기 `*_text` 포함), 문항별 응답 시간(ms, 다른 앱에 가 있던 시간 제외) |
| `events[]` | 새로고침, 노출 중 이탈, 저장 실패, 링크 변경 기록(최근 100개) |
| `openedAt`, `startedAt`, `finishedAt`, `updatedAt` | 화면 연 시각, 동의 시각, 종료 시각, 마지막 저장(기기 시계) |
| `serverCreatedAt`, `serverUpdatedAt` | 서버 시각 |
| `cond`, `vw`, `vh` | Q3에서 ‘눌러는 봤지만 가입하지 않음’ 여부, 화면 크기 |

이름·연락처 등은 수집하지 않습니다. `cond`, `vw`, `vh`는 원본에 있던 값입니다.

## 관리자 화면 (`/admin`)

- `admins/{uid}` 문서가 있는 이메일 계정만 사용할 수 있습니다. 응답은 ‘응답 불러오기’를 누를 때 한 번 읽습니다(실시간 구독 없음).
- **참여 현황**: 시작, 완료, 연령대별 완료, 진행 중, 이탈 추정(진행 중인데 마지막 저장 후 2시간 넘음), 중단(그만하기), 선별 탈락과 사유, 링크·연령 불일치, 반복 노출 수
- **모집 링크별 현황**: 링크별 시작·완료·연령대별 완료·불일치·탈락·중단·진행 중
- **문항별 응답**: 배너별로 묶어 전체 / 20~30대 / 50~60대 비교. 확신도 분포와 평균, 응답 시간 중앙값, 직접 쓴 답 목록
- **필터**: 테스트(제외/포함/테스트만), 진행 상태, 설문 버전, 모집 링크. 기본은 **테스트 제외 · 완료 응답**
- **응답 조회**: 응답별로 질문 문구, 고른 보기 문구, 확신도, 응답 시간, 노출 기록(설정·실제 시간)을 제시 순서대로 표시
- **CSV**: 원자료(응답 1건 = 1행, 코드값과 보기 문구 열, 직접 쓴 답, 보기 순서, 응답 시간, 노출 기록)와 집계(문항·보기·열별 수·분모·비율). 현재 필터가 적용됩니다.

집계 기준:
- 비율 = 선택 수 ÷ **그 문항에 답한 응답 수(n)**
- ‘답 없음’(분기로 건너뜀, 선택 문항 미응답, 도중 종료)은 따로 세고 분모에서 뺍니다
- 복수 선택 문항은 비율 합이 100%를 넘을 수 있습니다
- A1은 ‘먼저 눈에 들어왔다고 응답한 항목’으로 표시합니다. 참여자의 기억 응답이며 시선 추적 측정이 아닙니다
- CSV는 UTF-8 BOM을 붙여 엑셀에서 한글이 깨지지 않게 하고, `=`, `+`, `-`, `@`, 탭으로 시작하는 문자열 앞에 `'`를 붙여 수식으로 실행되지 않게 합니다
- 내려받은 CSV에는 응답 원자료가 들어 있으니 저장소에 올리지 마세요(`.gitignore`에 `*.csv` 포함)

## 보안

`firestore.rules`가 화면과 관계없이 접근을 막습니다.

- 비로그인: 응답 읽기·쓰기 불가
- 참여자(익명 인증): 자기 uid로 응답을 만들고, 진행 중일 때만 고치고, 자기 문서만 읽음. 전체 목록 조회, 남의 응답 조회·수정·삭제, 자기 응답 삭제 불가
- 고칠 수 없는 값: 소유자, 응답 ID, 설문 버전, 모집 링크, 배너 순서, 노출 설정, 테스트 표시, 서버 생성 시각
- 허용 필드 목록 외의 필드(예: `isAdmin`) 거부, 상태·링크 그룹 값, 타입, 목록 크기, 직접 쓰기 길이(기타 80자, 마지막 의견 600자), 서버 시각 검증
- 종료(완료·선별 탈락·그만하기) 후 참여자 수정 불가
- 관리자: `admins/{uid}`가 있는 계정만 전체 조회. 관리자도 앱에서는 응답 수정·삭제 불가(필요하면 콘솔에서)
- `admins` 컬렉션은 앱에서 누구도 쓸 수 없음(콘솔에서만 등록) → 참여자가 스스로 관리자가 될 수 없음
- 그 밖의 경로는 모두 거부

알아 둘 점:
- 익명 인증은 **브라우저별 응답 소유자**를 구분할 뿐, ‘실제 한 사람당 한 번 참여’를 보장하지 않습니다. 다른 브라우저·시크릿 창·저장공간 삭제로 다시 참여할 수 있습니다. 필요하면 **선택 사항**으로 참여자별 1회용 초대 코드를 나눠 주고 규칙에서 코드 사용 여부를 확인하는 방식을 추가할 수 있습니다(현재 미구현).
- 참여자는 규칙이 허용하는 범위에서 자기 응답 내용을 직접 조작할 수 있습니다(예: 존재하지 않는 보기 번호). 답 값 하나하나는 규칙에서 검사하지 않으므로, 분석 시 이상값을 확인하세요.
- Firebase 웹 설정값(API 키 등)은 비밀키가 아닙니다. 이 저장소에는 넣지 않았고, 배포된 Hosting이 `/__/firebase/init.json`으로 제공합니다. 서비스 계정 키는 쓰지 않습니다.
- 관리자 비밀번호는 Firebase Authentication에만 있습니다. 저장소에 넣지 마세요.

## 로컬에서 실행하기

필요한 도구: Node.js 20 이상, Java 21 이상(Firestore 에뮬레이터용).

```sh
npm install
npm run dev        # 에뮬레이터: 설문 http://127.0.0.1:5002, 에뮬레이터 UI http://127.0.0.1:4000
npm run seed       # 다른 터미널에서: 테스트 관리자 등록(에뮬레이터 전용)
```

- 설문: `http://127.0.0.1:5002/?group=young#test-t5`
- 관리자: `http://127.0.0.1:5002/admin` (계정은 `scripts/seed-emulator.mjs`의 에뮬레이터 전용 값)
- `localhost`·`127.0.0.1`에서 열면 자동으로 에뮬레이터(`demo-ad-survey`)에 연결되며 실제 프로젝트에는 아무것도 저장되지 않습니다. 에뮬레이터를 끄면 데이터도 사라집니다.

환경변수는 필요하지 않습니다. 시드 스크립트만 선택적으로 `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`를 읽습니다(`.env.example` 참고).

```sh
npm test           # 정적 테스트 + 보안 규칙 테스트(에뮬레이터 자동 실행). npm run dev가 켜져 있으면 끄고 실행
```

## Firebase 설정 (처음 한 번)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다(Spark 무료 플랜 유지, Google 애널리틱스는 필요 없음).
2. **프로젝트 설정 → 일반 → 내 앱**에서 웹 앱(`</>`)을 하나 등록합니다. Hosting이 이 앱의 설정을 `/__/firebase/init.json`으로 제공합니다. 표시되는 설정 코드는 저장소에 붙여 넣지 않아도 됩니다.
3. **Firestore Database → 데이터베이스 만들기**: Standard edition, 위치는 서울(`asia-northeast3`) 권장(나중에 바꿀 수 없음), **프로덕션 모드**로 시작합니다. 이후 규칙은 이 저장소의 `firestore.rules`로 배포합니다.
4. **Authentication → 시작하기 → 로그인 방법**에서 **익명**과 **이메일/비밀번호**를 사용 설정합니다.
5. 터미널에서:
   ```sh
   npx firebase login
   npx firebase use --add      # 만든 프로젝트를 고르고 별칭은 default (.firebaserc가 생기며 Git에는 올라가지 않음)
   ```

### 관리자 계정 등록

1. **Authentication → 사용자 → 사용자 추가**에서 관리자 이메일과 비밀번호를 만듭니다.
2. 만든 사용자의 **사용자 UID**를 복사합니다.
3. **Firestore Database → 데이터**에서 컬렉션 `admins`를 만들고, 문서 ID에 그 UID를 넣고 필드 하나(예: `note` = `관리자`)를 추가해 저장합니다.
4. `/admin`에서 그 계정으로 로그인합니다. 관리자를 빼려면 `admins/{UID}` 문서를 지웁니다.

## 조사 설계 확인 기록

확정된 사항:
- 연령대별 링크는 모집 경로만 구분하고 문항·보기·제외 조건은 같다
- 50~60대에만 광고 클릭 경험 제외 조건을 적용하는 것은 의도한 조건이다
- 링크 그룹 누락·잘못된 값·연령대 불일치는 기록하고 계속 진행한다

조사 담당자가 검토하면 좋은 점(구현은 원본대로 둠):
0. 40대·70대 이상은 참여 대상이 아닙니다(원본 설계). 40대를 받으려면 분석 집단, 전용 링크, 클릭 경험 조건 적용 여부를 정한 뒤 설문 버전을 올려 반영해야 합니다.
1. 50~60대가 Q3에서 ‘눌러 본 적이 없다’를 고르면 Q3_3(누르지 않은 이유)에 답한 뒤 종료됩니다. 이 답은 저장되지만 본 조사 대상은 아닙니다.
2. 20~30대가 Q3에서 ‘기억이 안 난다’를 고르면 Q3_1~Q3_3을 모두 건너뛰고 진행합니다.
3. 재노출이 생기면 참여자는 해당 배너를 설정 시간보다 오래 보게 됩니다. 관리자 화면의 ‘반복 노출’ 표시와 CSV의 `sN_restarts`, `sN_exposure_count`로 분석 포함 여부를 정하세요.
4. ‘그만하기’ 안내에는 ‘지금까지의 답은 분석에서 제외됩니다’라고 되어 있지만, 응답 자체는 `quit` 상태로 저장됩니다(기본 집계에서는 제외). 저장하지 않거나 삭제해야 하는지 연구 윤리 기준을 확인하세요.
5. 동의 화면의 소요 시간 ‘약 15분’이 실제 소요 시간과 맞는지 예비 조사에서 확인하세요.
6. M1(가장 이해하기 어려웠던 사진)은 화면에 ‘사진 1/2/3’(제시 순서)으로 보이지만 배너 번호로 저장됩니다. 관리자 화면·CSV는 배너 이름으로 표시합니다.

문항이나 조건을 바꾸면 `public/js/questions.js`의 `SURVEY_VERSION`을 올리고 이 문서에 변경 내용을 적어, 서로 다른 조건의 응답이 섞이지 않게 하세요(관리자 화면에서 버전별로 나눠 볼 수 있습니다).
