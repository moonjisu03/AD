# 광고 해석 설문

모바일 광고 배너를 사람들이 어떻게 받아들이는지 조사하는 대학원 프로젝트입니다. 20~30대와 50~60대의 응답을 수집하고 비교하는 것을 목표로 합니다.

현재 저장소에는 설문 화면과 진행 로직을 포함한 **`광고 해석 설문지.html`**이 있습니다. 이 파일을 기반으로 약 60명의 응답 자동 수집과 관리자 대시보드를 구현할 예정입니다.

> 현재는 초기 HTML 단계입니다. Firebase 연결, 관리자 인증, DB 보안 규칙, 실제 배포는 아직 구현되지 않았습니다. 이 파일을 그대로 배포해도 응답이 자동으로 모이는 상태가 아닙니다.

## 현재 설문 흐름

1. 조사 안내와 참여 동의
2. 연령대, 스마트폰 이용 빈도, 광고 클릭·가입 경험 등 기본 질문과 참여 대상 선별
3. 배너 3개에 대해 아래 절차 반복
   - 배너를 기본 10초 동안 표시하고 숨김
   - 기억나는 요소, 서비스 인식, 클릭 결과 예상 등을 질문
   - 배너를 다시 보여주며 비용·가입·문구·아이콘 해석과 확신 정도 등을 질문
4. 가장 이해하기 어려웠던 배너, 평소 확인 습관 등 마무리 질문
5. 제출 및 완료 번호 표시

배너 제시 순서와 일부 보기 순서를 바꾸는 로직, 문항별 응답 시간 기록, 노출 중 다른 탭이나 앱으로 이동하면 재노출하는 로직이 들어 있습니다. 배너를 눌렀을 때는 이미지를 확대하며, 가상 서비스 화면으로 이동하는 기능은 아직 없습니다.

실제 시선 추적을 수행하는 설문은 아닙니다. ‘먼저 눈에 들어온 항목’은 참여자가 응답한 내용으로 해석해야 합니다.

## 로컬에서 확인하기

```sh
git clone https://github.com/moonjisu03/AD.git
cd AD
```

현재 HTML은 별도 빌드 없이 브라우저에서 열어 화면 흐름을 확인할 수 있습니다. Python이 설치되어 있다면 작업 폴더에서 아래 명령으로 로컬 서버를 실행할 수도 있습니다.

```sh
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 열고 HTML 파일을 선택합니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 이 서버는 로컬 확인용이며 실제 조사 배포에 사용하지 않습니다.

현재 코드에는 주소 끝에 `#test`를 붙이면 테스트 응답으로 표시하는 기능이 있습니다. 단, 현재는 저장소가 연결되지 않았으므로 테스트 표시가 응답 자동 저장을 활성화하지는 않습니다.

## 현재 저장·연구자 메뉴의 상태

- `snapshot()`은 답변, 그룹, 진행 상태, 제시 순서, 응답 시간 등을 저장용 객체로 정리합니다.
- `writeNow()`는 실행 환경에 `window.claude.use('db')`가 있으면 해당 기능을 이용하려고 시도합니다. 이 파일만으로 해당 기능의 제공 여부나 실제 저장소를 확인할 수는 없습니다.
- 대체 전송 주소인 `CONFIG.endpoint`는 현재 비어 있습니다.
- 일반 브라우저에서 저장 기능이 제공되지 않으면 완료 화면에서 응답 내용을 복사해서 전달하도록 안내합니다.
- `adminPanel()`과 `showAdmin()`에는 간단한 인원 집계와 엑셀에 붙여넣기 위한 응답 복사 코드가 있지만, 실제 사용할 저장소와 관리자 권한 연결이 필요합니다.

**완료 번호가 표시되는 것과 DB에 응답이 저장되는 것은 별개입니다.** 실제 조사 전에는 저장 결과를 반드시 확인해야 합니다.

## 구현할 구성

하나의 웹사이트와 Firebase 프로젝트를 사용하는 방향입니다. 기존 HTML을 유지하면서 필요한 부분을 분리할 수 있으며, React 등으로 전면 재작성하는 것은 필수 사항이 아닙니다.

| 역할 | 예정 구성 |
| --- | --- |
| 설문 및 관리자 화면 배포 | Firebase Hosting |
| 응답 저장·조회 | Cloud Firestore Standard edition |
| 관리자 로그인·참여자 식별 | Firebase Authentication |
| 데이터 접근 제한 | Firestore Security Rules |
| 집계·그래프·결과 내보내기 | 직접 구현할 관리자 화면 |

무료 Spark 플랜 범위를 목표로 합니다. 고정 배너 이미지는 사이트와 함께 배포하고, 일반 **Firebase Hosting**을 사용합니다. App Hosting, Cloud Functions, Cloud Storage 등은 기본 구성에 포함하지 않습니다. 사용 서비스와 무료 한도는 설정 시 [Firebase 공식 요금표](https://firebase.google.com/pricing)에서 다시 확인합니다.

Firebase는 저장과 인증 등을 제공하며, 연구용 대시보드를 자동 생성해 주는 것은 아닙니다.

## 연령대별 참여 링크

연령대별 링크를 나누더라도 HTML이나 Firebase 프로젝트를 두 개 만들 필요는 없습니다. 예를 들어 같은 설문에 `?group=young`과 `?group=older`를 전달하는 방식으로 구현할 수 있습니다. **이 URL 처리 기능은 아직 구현되지 않았습니다.**

구현 전에 다음 사항을 확정합니다.

- 링크만 구분할지, 문항·보기·참여 제외 조건도 다르게 할지
- 링크의 모집 그룹과 참여자가 답한 연령대가 다르면 어떻게 처리할지
- 그룹 정보가 없거나 잘못된 링크로 접속하면 어떻게 안내할지

링크의 모집 그룹과 실제 응답 연령대는 별도로 저장합니다. 링크 정보는 수정될 수 있으므로 실제 나이나 접근 권한을 보장하는 값으로 사용하지 않습니다.

## 권장 작업 순서

1. 원본 설문을 실행하고 현재 흐름 확인
2. 연구자가 문항·분기·제외 조건과 대시보드 지표 확정
3. Firebase 프로젝트 설정과 테스트 환경 준비
4. 응답 저장, 중간 저장, 실패 재시도, 중복 제출 방지 구현
5. 관리자 로그인과 DB 보안 규칙 구현
6. 연령대별 참여 링크와 관리자 집계·그래프·다운로드 구현
7. 권한·저장·모바일 동작 테스트와 소수 인원 예비 조사
8. 확인된 버전 배포 후 본 조사 진행

배너 버튼을 통한 가상 화면 체험이 필요한지는 별도로 확정합니다. 설문 내용과 조사 조건을 구현자가 임의로 변경하지 않습니다.

### 조사 담당자에게 확인할 항목

현재 코드는 광고 클릭 경험이 없거나 기억하지 못하는 일부 50~60대 참여자를 종료시키지만, 20~30대에는 동일한 제외 조건을 적용하지 않습니다. 이것이 의도한 기준인지 확인한 뒤 유지하거나 수정해야 합니다.

## 저장 데이터와 관리자 화면

응답 ID, 설문 버전, 동의 여부, 모집 링크 그룹, 실제 연령 그룹, 배너 제시 순서, 노출 시간 설정, 답변·확신도·응답 시간, 시작·완료 시각, 진행 상태 등을 기록할 예정입니다. 이름·연락처 등 연구에 불필요한 정보는 추가하지 않습니다.

관리자 화면의 예정 범위는 다음과 같습니다.

- 시작·완료·진행 중·중단·선별 탈락 인원
- 연령대별 완료 인원과 배너별·문항별 응답 비교
- 테스트 응답 및 진행 상태 필터
- 원자료 및 집계 결과 다운로드

기본 집계에서는 테스트 응답을 제외하고 완료 응답을 사용합니다. 비율의 분모, 무응답 처리, 복수응답의 합계가 100%를 넘을 수 있다는 점을 명시합니다. 구현하지 않은 지표를 측정한 것처럼 표시하지 않습니다.

## 보안과 검증

- 일반 참여자는 자기 응답만 허용된 범위에서 저장하고, 다른 사람의 응답이나 전체 목록을 조회·수정·삭제할 수 없게 합니다.
- 관리자만 전체 응답을 조회할 수 있게 하고, 참여자가 스스로 관리자 권한을 부여할 수 없도록 합니다.
- 화면에서 메뉴를 숨기는 것에 그치지 않고 DB 보안 규칙으로 접근을 제한합니다.
- 서비스 계정 키, 관리자 비밀키, 실제 응답 데이터와 내보낸 결과 파일은 Git에 올리지 않습니다.
- Firebase 웹 설정값 자체를 비밀 접근키로 취급해 보안을 대신하지 않습니다. 접근 통제는 인증과 보안 규칙으로 수행합니다.
- 저장 성공을 확인한 뒤에만 성공 안내를 표시합니다.
- 비로그인·일반 참여자의 직접 DB 접근 차단, 권한 위조, 중복 제출, 새로고침, 네트워크 실패를 테스트합니다.
- 이미지 준비 후 노출 타이머가 시작되는지와 모바일에서 끝까지 응답할 수 있는지 확인합니다.

아직 실제 실행 및 보안 검증이 완료된 버전이 아닙니다. 테스트 결과는 구현 후 이 문서에 추가합니다.

## GitHub 협업

- 작업 시작 전 최신 변경을 받아 충돌을 줄입니다.
- 기능별 브랜치와 의미 있는 커밋을 사용하고, 검토할 변경은 Pull Request로 공유하는 것을 권장합니다.
- 검토자는 GitHub 저장소 협업자로 초대합니다. 코드 검토에 Firebase 실제 응답 데이터 접근 권한까지 필요한 것은 아닙니다.
- 설문 문항을 변경할 때는 이유와 변경 내용을 기록합니다. 본 조사 시작 후에는 설문 버전을 구분해 서로 다른 조건의 응답이 섞이지 않도록 합니다.

Firebase 설정, 관리자 등록, 보안 규칙 배포와 사이트 배포의 구체적인 명령은 구현이 완료되면 추가합니다.
